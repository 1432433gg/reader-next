# 新章节自动检查

服务端会定时检查书架上所有网络书有没有新章节，有更新就记下来，书架上直接能看到。

## 它做了什么

1. 每隔 `CHAPTER_UPDATE_INTERVAL_HOURS` 小时（默认 24）跑一次，服务启动 1 分钟后跑第一次；重启服务不会马上重跑，而是按上次检查时间往后算。
2. 遍历每个用户的书架，跳过本地书籍（TXT/EPUB/PDF/MOBI）、标记为「不更新」的书和书源已禁用的书。
3. 对每本书强制重新拉取目录，章节数变多就更新书架里的「共 N 章」「最新章节」，目录缓存也一起刷新，打开书就能看到新章节。
4. 同一个书源的书一本接一本检查，中间隔 1.5 秒；不同书源同时检查（默认 3 个），避免短时间内大量请求同一个网站被封。

## 在书架上看结果

- 有更新的书在书名右边显示「新 N 章」。多次检查发现的新章节会累计，**打开这本书之后标记消失**。
- 封面右上角的数字是未读章节数（总章数减去已读位置），新章节进来后会跟着变大。
- 点书架上的「刷新书架」（刷新按钮）会马上检查一次当前账号的书架，检查在服务端后台进行，完成后刷新书架并弹出结果。

## 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CHAPTER_UPDATE_INTERVAL_HOURS` | `24` | 自动检查间隔（小时），设为 `0` 关闭自动检查（手动检查仍可用） |
| `CHAPTER_UPDATE_CONCURRENCY` | `3` | 同时检查的书源数量 |

Docker 部署时在 `.env.docker` 或 `docker run -e` 里设置即可。

## 检查失败怎么办

手动检查后提示「N 本书检查失败」，通常是书源失效、网站改版或暂时连不上。打开这本书换个书源（阅读页「书源」），下次检查会用新书源。

## API

- `GET /reader3/getChapterUpdateStatus`：返回是否开启、间隔、是否正在检查、上次/下次检查时间，以及当前用户最近一次检查结果（`report`）。
- `POST /reader3/checkChapterUpdates`：在后台立即检查当前用户的书架，返回 `{"started": true}`；已经有检查在进行时返回 `false`，轮询状态接口直到 `running` 为 `false`。

`report` 字段：

| 字段 | 说明 |
| --- | --- |
| `checked` / `updated` / `failed` / `skipped` | 本次检查的书数、有更新的书数、失败数、跳过数 |
| `newChapters` | 本次发现的新章节总数 |
| `updatedBooks` | 本次有更新的书 |
| `failedBooks` | 本次失败的书和原因 |
| `pendingBooks` | 累计还没读的新章节（书架「新 N 章」标记用这个） |
